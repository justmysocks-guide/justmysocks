## 我是怎么测的（方法公开，你可以复现）

测速这事最怕两点：一是只测一次就下结论，二是测的根本不是 JMS 节点。所以方法先写清楚：

1. **工具**：用本组织开源的一键脚本 [jms-speedtest](https://github.com/justmysocks-guide/jms-speedtest)，它测四样东西——当前出口 IP、到 ChatGPT、Claude、Gemini 的连通状态。跑法只有一行：
   ```bash
   curl -sSL https://raw.githubusercontent.com/justmysocks-guide/jms-speedtest/main/check.sh | bash
   ```
   注意：必须确认流量真的走了节点再认结果——先用 `curl -x http://127.0.0.1:10809 -s https://ifconfig.me/ip` 核对出口 IP 等于节点 IP。在 Windows 上 `python check.py` 不认代理环境变量，会直连、测到的是本地网络不是节点（2026-11-15 实测踩过这个坑）。
2. **分三档测，不只测一次**：同一个套餐默认给 5 条线路。先用默认节点跑一次，再手动指定 s3 跑一次、s4 跑一次——因为按官方线路说明，s1 / s2 是普通骨干线路，s3 / s4 是电信 CN2 GIA / 联通 9929 优化线路，s5 是移动 CMI 线路。只测默认节点，等于只测了最普通的那两条。
3. **晚高峰测**：白天不卡不代表晚上不卡，实测统一在晚高峰时段做，表里会写每次的日期和时段。
4. **再加两项实际体验检查**：YouTube 4K 视频能不能秒开并稳定播放、下载一个大文件看实际速度。这两项不进脚本，手动记。
5. **结果只认当次实测**：线路状态会变，表里每个数字都带日期；不写“永远快”“永不卡”这种话。

## 速度慢，先查这三件事

这是排障经验，不是实测结论，但能解决大多数“慢”的问题：

1. **先看你用的是哪条线路。** 套餐默认的 5 条线路里，s1 / s2 是普通骨干，晚高峰最容易挤；s3 / s4 是优化线路。客户端里手动指定 s3 或 s4，或者开 URL-Test 让它自动选延迟最低的。详细步骤在 [Clash 教程](../clash/)，问答在 [Issue #2](https://github.com/justmysocks-guide/.github/issues/2)。
2. **再看是不是全局代理。** 全局模式下国内软件也走代理，又慢又容易触发风控。规则分流（国内直连、海外走加速）才是正常用法，规则集在 [clash-rules](https://github.com/justmysocks-guide/clash-rules)。
3. **最后看是不是节点本身被墙。** JMS 的机制是后台自动换新 IP，客户端刷新一次订阅就能拿到新地址；如果刷新后还是不行，再去后台提交工单。退款与售后规则见 [Issue #12](https://github.com/justmysocks-guide/.github/issues/12)。
